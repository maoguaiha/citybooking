## Spec 必带项（§7.0 · 按改动类型）

写 Spec 时，除「不改什么」段外，**按本次改动类型补必带项**——AI 才知道边界在哪。改动类型可叠加。任何高风险链路同时套用 ①~④（见 [redlines.md §7.1](redlines.md#sec71)）。

| 改动类型 | Spec 必带项 | 对应审查维 |
| --- | --- | --- |
| 扣减 / 库存 / 抢购 / 防重 | 部署实例范围（单/集群）；校验+扣减原子（放一处）；真相源唯一；幂等兜底 | ⑧ |
| 缓存 / 列表 / 导出 / 批量 | 对象短寿命；缓存必须上限+过期；列表/导出分页或流式；JVM 含 `-Xms=-Xmx` + `HeapDumpOnOutOfMemoryError` | ⑨ |
| 异步 / 定时 Job / 批量 / 限流 | 实例范围；用池禁 `new`；队列有界+拒绝=CallerRunsPolicy；真相源+幂等+限流 | ⑩ |
| 加 Spring Bean / 接中间件 / 加配置 | 用 starter；**优先构造器注入**（推荐 Lombok `@RequiredArgsConstructor`），仅循环依赖等无解场景允许 `@Lazy`/字段注入并加注释；配置走 `${ENV:default}`；自定义 bean 用 `@ConditionalOnMissingBean` | ⑦ |
| Web 层 / 接口 / Controller | 统一返回 `Result<T>`；参数走 `@Validated`+DTO 注解；异常交 `@RestControllerAdvice`；RESTful 动词正确 | ⑪ |
| 数据层 / 加表 / 改 Entity / 写 SQL | 业务表一律逻辑删；`update`/`remove` 必须带 Wrapper 或 byId；列表/导出分页或流式；条件用 `LambdaQueryWrapper` 禁拼 SQL；主键 `ASSIGN_ID` | ⑫ |
| 事务 / AOP / 切面 / 幂等 / 限流 | 标清真相源（单库或本地 DB+本地消息表同库才用 @Transactional；含 Redis/MQ/HTTP 等**已提交外部操作**禁用单库事务回滚）；事务只包单库 JDBC；一律 `rollbackFor=Exception.class`；横切逻辑抽成注解+@Aspect/拦截器 | ⑬ |
| 可靠消息最终一致性（本地消息表） | 建本地消息表（与业务同库）；@Transactional 仅包本地 DB+消息表；消息由独立任务投递 MQ；下游幂等+对账 | ②/⑬（本模式自动豁免 @Transactional 跨系统审查） |
| Redis / 缓存 / 异步 / 定时任务 / 监控 | 缓存必须 TTL 或容量上限；跨实例用 Redisson(禁手写裸锁)；跨服务异步走 MQ；@Async 必配自定义池；多 Redis Bean 用 @Qualifier；生产开 Actuator | ⑭ |
| 微服务拆分 / 加服务 / 跨进程调用 | 按业务域拆；跨服务通信明确(Feign+熔断 / MQ 最终一致)；数据归属单一；一致性用 MQ/Saga 禁套单机事务；走绞杀者模式 | ⑮ |
| 服务发现 / 配置中心 / 网关 / Feign | 服务地址走 `{{注册中心}}`(禁硬编码IP)；动态配置进 `{{配置中心}}`+@RefreshScope(禁字面量写死)；`{{RPC客户端}}`(默认 OpenFeign) 必带熔断降级；`{{网关}}`(默认 Spring Cloud Gateway) 配路由超时+限流；禁循环依赖 | ⑯ |
| 可观测 / 容器化 / 上线运维 | 配 Actuator health 作 K8s 探针且探真依赖；链路追踪采样本环境 1.0/生产 0.1 且 traceId 透传；镜像多阶段构建+非 root；配置外部化；日志落 stdout+JSON+traceId 进 MDC | ⑰ |
| 任何高风险链路 | 同时套用 ①~④ | ①~④ |

### §7.0 代码模板联动（设计即代码）

> 选定改动类型后，Agent 除遵循上表「对应审查维」外，应自动套用 [代码生成模板](代码生成模板.md) 中的预设骨架，从源头杜绝违规。模板编号 CT-XX 与下表对应；新模板在 代码生成模板.md 追加。

| 改动类型 | 审查维 | 对应代码模板 |
| --- | --- | --- |
| 加 Spring Bean / 接中间件 / 加配置 | ⑦ | CT-07 构造器注入（@RequiredArgsConstructor） |
| 事务 / AOP / 可靠消息模式 | ⑬ / ② | CT-13 本地消息表 + @Transactional 骨架 |
| 缓存 / 列表 / 导出 / 批量 | ⑨ | CT-09 有界缓存（Caffeine+上限/TTL） |
| 数据层 / 加表 / 改 Entity | ⑫ | CT-12 分页 + LambdaQueryWrapper |
| Redis / 异步 / 定时任务 | ⑭ | CT-14 Redisson 锁（finally unlock） |

## 占位符落地动作（agent 在 01-init 执行）

> 上表 `{{...}}` 不是装饰：agent 在 01-init 的「占位符落地」步骤里，要把**能确定**的占位符**批量替换为真实值并写回**——
> - 技术栈 / `{{框架A/B/C}}` / **`{{注册中心}}` `{{MQ}}` `{{RPC客户端}}` `{{网关}}` 等插槽** / 用户给定项 → 写进 `STATE.md` 与项目信息卡（这是生成专属 redlines 的前提）；
> - `{{测试运行命令}}`、各 grep 锚点（①~⑰）→ 写进 `PROJECT-FLOW.md` 或对应 `spec-*.md`；
> - 代码 derive 出的风格 / 真相源 / 红线 → 写进 `STATE.md` 供后续节点复用。
> **未填完不许进 Phase 2**：尤其是「技术栈确认」必须把 `{{注册中心}}`/`{{MQ}}`/`{{RPC客户端}}` 等替换为真实组件，否则 redlines 的 grep 仍是占位符、查不到，后面全空转。
