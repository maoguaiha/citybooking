## CT-07 构造器注入（对应维度 ⑦）

**适用**：加 Spring Bean / 接中间件 / 加配置。
**规约**：优先构造器注入（final 字段）；循环依赖无解时才用 `@Lazy`/字段注入并加注释（见 redlines ⑦a）。

### 方案 A：Lombok（推荐）
```java
@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderRepository orderRepository;   // final 字段 = 构造器注入
    private final PayClient payClient;                // 被注入方若非 Spring 托管，请改 @Component 或在配置类 @Bean
}
```

### 方案 B：手写构造器（无 Lombok）
```java
@Service
public class OrderService {
    private final OrderRepository orderRepository;

    public OrderService(OrderRepository orderRepository) {
        this.orderRepository = orderRepository;
    }
}
```

### 例外（循环依赖无解）
```java
@Service
public class AService {
    // 仅当 A<->B 循环依赖无法解开时，才允许字段注入 + @Lazy，且必须注释原因
    @Lazy
    @Autowired
    private BService bService; // TODO: 循环依赖临时方案，待解耦后改回构造器注入
}
```

## CT-13 可靠消息最终一致性（本地消息表）（对应维度 ②/⑬，自动豁免 @Transactional 审查）

**适用**：Spec 勾选「可靠消息最终一致性（本地消息表）」改动类型。
**规约**：本地 DB 操作 + 本地消息表插入放在**同一个 @Transactional** 内（同库），保证原子；消息由独立任务/事务日志投递到 MQ，下游靠幂等+对账。因此本模式**自动豁免** redlines ②/⑬ 中关于「跨系统套单库事务」的打回。

```java
// 1) 本地消息表（与业务表同库）
// CREATE TABLE local_msg (
//   id BIGINT PRIMARY KEY, biz_id VARCHAR(64) UNIQUE,
//   payload JSON, status TINYINT, create_time DATETIME
// );

@Service
@RequiredArgsConstructor
public class ReliableProducer {
    private final BizMapper bizMapper;
    private final LocalMsgMapper localMsgMapper;

    // 2) 同库事务：业务落库 + 消息落库 原子绑定
    @Transactional(rollbackFor = Exception.class)
    public void createOrderWithMessage(Order order, String payload) {
        bizMapper.insert(order);
        localMsgMapper.insert(new LocalMsg(order.getId(), payload, Status.INIT));
    }

    // 3) 独立投递（不在 @Transactional 内）：扫描 INIT 消息发 MQ，成功置 SENT；失败靠定时对账
    @Scheduled(fixedDelay = 1000)
    public void deliver() {
        List<LocalMsg> pending = localMsgMapper.selectByStatus(Status.INIT);
        for (LocalMsg m : pending) {
            mqTemplate.send(topic, m.getPayload());   // 外部 MQ：失败不影响本地事务
            localMsgMapper.markSent(m.getId());
        }
    }
}
```
> 注意：`@Transactional` 只包本地 JDBC（Biz + LocalMsg 同库）。**不要**把 `mqTemplate.send` 放进该事务——那正是 redlines ⑬a 禁止的「用单库事务回滚已提交外部操作」。下游消费端必须幂等。

## CT-09 有界缓存（对应维度 ⑨）

**适用**：缓存 / 列表 / 导出 / 批量。
**规约**：缓存必须上限+TTL；禁止 `static Map` 只加不删。

```java
// Caffeine：自动上限 + 过期，合法
private static final Cache<String, User> USER_CACHE = Caffeine.newBuilder()
        .maximumSize(10_000)
        .expireAfterWrite(Duration.ofMinutes(10))
        .build();
```
> 若确需 `static Map`，必须 `final` 且配 `@PostConstruct` 初始化 / `@PreDestroy` 清理或显式上限过期，否则命中 ⑨a 打回。

## CT-12 分页 + LambdaQueryWrapper（对应维度 ⑫）

**适用**：数据层 / 加表 / 改 Entity / 写 SQL。
**规约**：列表/导出分页或流式；条件用 LambdaQueryWrapper 禁拼 SQL；update/remove 必须带 Wrapper 或 byId。

```java
Page<Order> page = orderMapper.selectPage(
        new Page<>(req.getPage(), req.getSize()),
        Wrappers.<Order>lambdaQuery().eq(Order::getUserId, uid).gt(Order::getCreateTime, from));
```

## CT-14 Redisson 分布式锁（对应维度 ⑭）

**适用**：Redis / 缓存 / 异步 / 定时任务 / 监控。
**规约**：跨实例互斥用 Redisson（禁手写裸锁）；锁必须在 `finally` 释放。

```java
RLock lock = redissonClient.getLock("order:" + orderId);
try {
    lock.lock(10, TimeUnit.SECONDS);
    // 临界区
} finally {
    if (lock.isHeldByCurrentThread()) lock.unlock();
}
```
