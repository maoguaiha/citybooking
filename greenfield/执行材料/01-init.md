# Phase 1 · 初始化与框架选型(greenfield / A0)

> 本节点只做 **A0 框架选型**（greenfield 起点）。项目信息卡在此填充；（存量项目无此步，由 B0 摸底替代）。

## 动作（agent 执行，用户拍板）

1. **填充项目信息卡**：把 [spec-template.md §项目信息卡](../参考文件/spec-template.md#infocard) 的 `{{...}}` 填进 `../运行时/STATE.md` 或本节点顶部。
2. **占位符落地（硬门槛）**：把能确定的 `{{...}}` 批量替换为真实值并写回——
   - 技术栈 / `{{框架A/B/C}}` / 用户给定项 → `../运行时/STATE.md` + 项目信息卡；
   - `{{测试运行命令}}`、各 grep 锚点（①~⑰）→ `../运行时/PROJECT-FLOW.md` 或对应 `spec-*.md`；
   - **未填完不许进 Phase 2**（否则 grep 三连查空、测试跑不起）。
3. **澄清产品方向**：若 `{{产品方向}}` 不明确 → 触发 [不确定就问](../参考文件/roles.md#ask) 向用户确认（做什么、给谁用、核心差异点）。
4. **检索候选框架**：从 GitHub / 开源平台检索 **≥3 个**契合方向的成熟框架。
   - 维度：语言/运行时、架构范式、社区活跃度（Stars、近 3 月提交、Issue 响应）、可改性、许可（MIT/Apache 可否商用）。
5. **出对比表（必须 ≥3 个，附一句话推荐理由与风险）**：

   | 框架 | 语言/栈 | 成熟度 | 社区活跃 | 可改性 | 许可 | 契合度 | 风险/坑 |
   | --- | --- | --- | --- | --- | --- | --- | --- |
   | `{{框架A}}` | | | | | | | |
   | `{{框架B}}` | | | | | | | |
   | `{{框架C}}` | | | | | | | |

6. **⚠️ 必须交用户拍板**：agent 不得自行定框架。把对比表 + 倾向建议给用户，等选择（命中 [不确定就问](../参考文件/roles.md#ask) 任一情况须先问）。
7. **选定后起步**：
   - clone / fork 选定框架 → 跑通 demo / hello world（验证本地环境）。
   - 读源码与约定 → **derive 本项目风格约束**（见 `../执行材料/03-coding.md` A4）→ 进入 A1 写需求文档（`../执行材料/02-spec.md`）。
   - 全程以「框架已有能力」为底座，新功能在其上叠加，**避免重写**。
